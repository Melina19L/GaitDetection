# NeuroPulse Analyzer - Project Context & Guide

## Project Scope
This project focuses on the **Development of Transcutaneous Spinal Cord Stimulation (tSCS) and Functional Electrical Stimulation (FES) Strategies for Gait Rehabilitation**, with a specific focus on addressing Freezing of Gait in Parkinson's Disease. 

The core of the project is a Python-based GUI (built with PySide6) that performs **real-time gait detection** using IMU sensors and FSRs (Force Sensing Resistors). It tracks joint angles (ankle dorsi/plantarflexion, hip, trunk) and identifies key gait cycle phases (such as Heel Strike and Toe Off using gyroscope peak/valley detection) to trigger closed-loop neuromodulation.

## Directory & Data Management
The application employs a dynamic, OS-independent file management system for clinical data:

**Base Data Path:**
- **macOS:** `~/Library/Application Support/NeuroPulse Analyzer/NeuroPulseAnalyzer_Dataset/phase1`
- **Windows:** `%APPDATA%\Programs\NeuroPulse Analyzer\NeuroPulseAnalyzer_Dataset\phase1`
- **Linux:** `~/.local/share/NeuroPulse Analyzer/NeuroPulseAnalyzer_Dataset/phase1`

*(Note: Fallback is `NeuroPulseAnalyzer_Dataset/phase1` in the local workspace directory if the above paths fail).*

**Data Organization:**
- **Session/Patient Subdirectories:** Dynamically generated based on the patient's name and session info inputted via the GUI.
- **Saved File Types:**
  - `*.pkl`: Serialized databases containing complete session recordings and sensor data streams.
  - `*.xlsx`: Unified workbook with sheets for joint angles, raw IMU streams (one sheet per sensor), FSR streams, and stim events. *(Sole destination for raw data — replaces the legacy `raw_data/` folder and `*_joint_angles.csv` file, both removed.)*
  - `*_plot.pkl`: AngleCalibrator buffers for offline replay/plotting.

## Core Architecture
- **`gui/`**: Contains the PySide6 frontend (Main Window, Pages, Widgets). The main entry point for UI setup and interactions is `gui/uis/windows/main_window/setup_main_window.py`.
- **`stimulator/`**: Handles backend logic, including serial communication for the stimulator, stimulation parameters, closed-loop control triggers (`closed_loop.py`), and the biological gait phase models.
- **`ble/`**: Manages Bluetooth Low Energy connections, specifically containing the `FSRController` for real-time foot pressure data and the IMU `BLEScanner`.
- **`offline_gait_analyzer.py`**: A standalone script used to validate and refine the real-time detection algorithms on pre-recorded `.pkl` data.
- **`angle_calibrator.py`**: Manages the functional calibration procedure to biomechanically align and center IMU angles (e.g., setting ankle to 0° during quiet standing).

20. **Calibration Offset Averaging + Signed Relative-Quaternion Ankle Algorithm:** Two coupled fixes for physiological joint-angle accuracy.
    - **Averaged calibration**: `Calibrate Offsets` previously grabbed a single quaternion sample per joint, which introduced ±5–15° jitter into the captured offsets (the standing-pose hip read +11° instead of 0° even when the subject was perfectly still). Replaced single-shot `__get_latest_quaternion_nonblocking` with a new `__get_averaged_quaternion(inlet, duration_s=1.0)` helper that collects ~60 samples over 1 s and returns their quaternion-aware mean (sign-flips samples whose dot-product to the running reference is negative, then renormalises). All three `_one_side_*` calibrators now use it. Standing-pose readings now sub-degree.
    - **Signed ankle algorithm**: the legacy unsigned `arccos(angle(shank-X, foot-Y))` was inherently contaminated by knee flexion — a bent knee tilts the shank, which tilts the shank-X axis in world frame, which artificially changes the angle to any foot-fixed axis even when the ankle didn't move. Result: ±55° spurious ankle swings during walking. New `signed_ankle_angle(q_shank, q_foot, q_shank_ref, q_foot_ref, foot_axis)` in `closed_loop.py` computes the change in shank-in-foot relative orientation since calibration, then projects it onto the ankle's medio-lateral axis (auto-detected `foot_axis`, typically `Y` for the user's mounting) via `twist_angle_around_axis`. This is independent of shank tilt by construction and the projection filters out inversion/eversion contamination. `ROM.calculate_ankle_angle` now accepts optional `q_shank_ref` / `q_foot_ref`; when present, it dispatches to the new signed algorithm; otherwise falls back to the legacy unsigned math (back-compat for old saves). The calibrator threads its stored `*_ankle_qshank_ref` / `*_ankle_qfoot_ref` (averaged at calibration) through `__compute_angles_from_data` for both sides.
    - Affected files: [angle_calibrator.py](FES/GUI/angle_calibrator.py), [closed_loop.py](FES/GUI/stimulator/closed_loop.py).
21. **Ankle Math Reverted to Knee-Style (simplicity over over-engineering):** The signed-relative-quaternion ankle algorithm introduced in milestone 20 — together with auto-detected foot axis = `Y` — produced ±150–300° spikes in field tests on the user's mounting. Since the knee algorithm (`unsigned arccos(angle(thigh-X, shank-X)) - offset`) was implemented by a previous developer and works cleanly in physiological range, the user requested ankle and hip follow the same pattern instead of inventing dedicated math. Reverted: `__compute_angles_from_data` no longer takes `is_ankle` / axis / ref-quaternion parameters; `_one_side_ankle` no longer auto-detects axes; both ankle compute branches in `record_data` now call the same plain `ROM.calculate_joint_angle` path that knee/hip use, just with the shank+foot inlet pair. Calibration averaging (1 s mean, milestone 20a) is kept — it's an unrelated stability improvement that helps every joint. The `signed_ankle_angle`, `twist_angle_around_axis`, and axis-detection helpers in `closed_loop.py` are kept as dead code for future experiments but are no longer wired into the runtime path. Affected file: [angle_calibrator.py](FES/GUI/angle_calibrator.py).
22. **Ankle Math via Relative Quaternion + scipy Euler (decoupled from knee/hip):** Field testing showed the ankle plot still picked up knee flexion ("when I bend the knee, the ankle plot reads ±50°"). The previous geometric sagittal-plane projection (milestone 20 attempt) was mathematically defensible but fragile in practice. Replaced `signed_ankle_angle` body in `closed_loop.py` with the textbook biomechanics approach (Hoegberg 2025 ReBAIT, Wu 2002 ISB):
    - `q_rel = q_shank⁻¹ · q_foot` — orientation of foot expressed in the shank's local frame. Independent of where the shank is in the world: knee/hip motion cancels by construction.
    - `q_delta = q_rel_now · q_rel_ref⁻¹` — change since the calibration pose, so neutral standing reads 0°.
    - `scipy.spatial.transform.Rotation(q_delta).as_euler(order, degrees=True)` — robust handling of quaternion double-cover and gimbal lock. The Euler order is picked so the FIRST component is rotation around the shank's medio-lateral axis (`shank_ml_axis`, default 'Y' for the user's Movella DOT button-up mounting): that's sagittal-plane dorsi/plantarflexion. Frontal and transverse components discarded.
    - Knee + hip code paths **untouched** (user's explicit constraint) — they still use the original `unsigned arccos(angle(thigh-X, shank-X)) - offset` formula and continue to work as before.
    - Verified mathematically: with quaternion test vectors representing a 60° knee flexion and 0° ankle motion, the new function returns 0.00° (perfect decoupling); with knee 60° + ankle 15° dorsiflexion, returns +15.00°.
    - References for thesis: Hoegberg, Donahue, Major (2025) *Sensors* 25(9), 2931; Wu et al. (2002) ISB recommendations *J Biomech*; Grood & Suntay (1983) JCS *J Biomech Eng*.
    - Affected file: [closed_loop.py](FES/GUI/stimulator/closed_loop.py).
23. **Functional Calibration (PCA sensor-to-segment alignment, Hoegberg ReBAIT 2025):** Field tests after milestone 22 still showed ~10° baseline shift on ankle when knee changed by ~50°. Root cause: sensor mounting tilt — the IMU's local Y axis is not perfectly aligned with the anatomical knee/ankle medio-lateral axis. The static "Calibrate Offsets" cannot fix this because it captures only one pose. Implemented Hoegberg's PCA-based functional calibration:
    - **`compute_axis_alignment_quaternion(gyro_samples, target_axis='Y')`** in `closed_loop.py`: PCA on Nx3 angular-velocity vectors → first principal component = axis of maximum rotation in sensor's local frame = anatomical joint axis. Builds a quaternion (with sign disambiguation) that rotates this axis onto the target anatomical Y.
    - **`AngleCalibrator.start_functional_calibration(duration_s=5)`**: starts a buffering window during which `record_data` accumulates gyro vectors per sensor (`left_shank`, `left_foot`, `right_shank`, `right_foot`). After `duration_s` seconds, runs PCA per sensor, stores `self.{left,right}_{shank,foot}_align_quat`.
    - **`signed_ankle_angle`** updated to accept `q_shank_align` / `q_foot_align`. When provided, applies them to both runtime and reference quaternions (`q = q_imu * q_align`) before the relative-quaternion + Euler decomposition. Default None → behaves exactly as in milestone 22 (back-compatible).
    - **GUI**: new `Functional Calibration` button on the IMU Setup page next to `Calibrate Offsets`. User flow: connect sensors → Calibrate Offsets (static) → Functional Calibration (walk normally for 5 s). Status box reports the captured alignment quaternions.
    - **Verified mathematically**: with synthetic gyro data simulating a 10° sensor mounting tilt, PCA recovers the true axis to 0.04° accuracy; the ankle angle is then computed correctly regardless of how the leg is rotated as a rigid body.
    - References for thesis: Hoegberg, Donahue, Major (2025) *Sensors* 25(9), 2931 § 2.1.2; Picerno (2008) *J Biomech*.
    - Affected files: [closed_loop.py](FES/GUI/stimulator/closed_loop.py), [angle_calibrator.py](FES/GUI/angle_calibrator.py), [setup_main_window.py](FES/GUI/gui/uis/windows/main_window/setup_main_window.py).
